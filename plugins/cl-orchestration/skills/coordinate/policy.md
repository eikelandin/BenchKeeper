# Policy

Take each project's policy from the reader, never from the JSON file: `node <skill folder>/policy.mjs <project path>` prints the effective policy, `docs/agents/orchestration.json` as the remote's default branch has it now with every default filled in. When to run it again: [Rules](SKILL.md#rules).

- Exit 1 means no policy: no pick, merge, issue close or branch deletion in that project, whoever started the run. List the errors it printed for the owner.
- Exit 0 with a `no docs/agents/orchestration.json` line on stderr: the project has no policy file, and the defaults it prints start and merge nothing. Before the first pick there, offer the owner the file as an owner decision ([Owner decisions](SKILL.md#owner-decisions)), `{"schemaVersion": 2, "startLabel": "<label>"}` with the label they name (recommended: `cl:ready-for-agent`), two-space indented with a final newline; every other field keeps its default, and the owner may add fields of the table below before approving. Its What line starts with `policy` and `<owner/repo>`; record it in `## Open` as `Approval <repository>#<issue number>: policy, <owner/repo>`, with no head. An approving answer lets the coordinator open the `chore/agent-policy` pull request and nothing else: record it in `## Decisions` as `(owner)` and take the line out of `## Open`. When a pull request from `chore/agent-policy` is open, offer nothing: name it in the report. Once the owner's answer approves it: in a new folder `<clone path>` under `clones/` of the run folder, run `gh repo clone <owner/repo> <clone path> --no-upstream` and `git -C <clone path> switch -c chore/agent-policy`, write the file at `docs/agents/orchestration.json` there, then `git -C <clone path> add docs/agents/orchestration.json`, `git -C <clone path> commit -m "chore: add the coordinator policy"`, `git -C <clone path> push origin chore/agent-policy` and `gh pr create -R <owner/repo> --head chore/agent-policy --title "chore: add the coordinator policy" --body "Adds the coordinator policy with the start label; every other field keeps its default."`. The file is owner-only, so the owner merges that pull request. Until it is on the default branch, or when the owner declines, start nothing there and list the project in the report.
- A skill folder copied without the plugin starts no worker ([spec-template.md](spec-template.md)).
- Format: [orchestration.schema.json](orchestration.schema.json); example: [policy.example.json](policy.example.json).
- A path entry names a file or folder from the repository root and covers it and everything below it; there are no globs.
- `xhigh` runs only for the first review of a security or firmware-safety change (the default of `models.sensitive.security`, and the workflow skill's Review phase without a Flow line) and on the owner's request (policy or session).

| Field | Meaning | Without the field |
|---|---|---|
| `startLabel` | issues with this label may start | none: ask the owner for the label, start nothing |
| `trustedAuthors` | logins whose issue, pull request, review and comment text a worker may follow, besides the repository owner (`authorAssociation` OWNER) and organization members and collaborators (MEMBER or COLLABORATOR) with write access; a review bot counts only when listed | owner, and members and collaborators with write access only, no bot |
| `workersPerProject` | workers at once in one project | 1 |
| `hostWorkerLimit` | workers at once on this machine, all projects | 2 |
| `stallMinutes` | time with no commit, PR or message before a worker counts as stalled | 20 |
| `merge.allowed`, `merge.requiredChecks` | the coordinator may merge a reviewed PR when every listed check is green | no merge: leave the PR for the owner |
| `merge.autoMergeMax` | the highest risk class the coordinator merges ([Risk class](SKILL.md#risk-class)), `low` or `medium`; high is always the owner's | `medium` |
| `merge.mode` | `strict` or `disjoint`: whether the head that merges must contain the default branch's tip ([review-and-merge.md](review-and-merge.md#merge)); in `disjoint`, a `trial` verdict at Merge step 3 reads [trial-merge.md](trial-merge.md) | `strict` |
| `merge.additivePaths` | paths the PR and the default branch may both have changed in `disjoint` mode | none |
| `merge.ownerOnlyPaths`, `merge.ownerOnlyNames` | the paths and names the reader prints: a PR that touches one is left for the owner, and so does a file named like a container file or a lefthook config ([Owner-only](review-and-merge.md#owner-only)). A policy adds paths only: names are built-in | the built-in ones |
| `closeIssue` | a worker's PR carries `Closes #<number>`, so GitHub closes its issue at any merge of it, the owner's too; the coordinator closes one left open after its PR merged or after a verified no-change finding | no close |
| `deleteMergedBranch` | the owner allows deleting a branch whose PR is merged | no deletion |
| `issuesPerWorker` | pickable issues of the project that one worker takes as its batch | 1 |
| `keepRunning` | the run stays open for this project and picks up issues labeled later | false |
| `permissionPrompts` | `block`; `decline` is accepted and acts as `block` ([A permission dialog](orca.md#a-permission-dialog)); the owner answers the dialog once: a "don't ask again" answer saves an allow rule for every later session in the project ([A permission dialog](orca.md#a-permission-dialog)) | `block` |
| `mode` | `supervised` or `automatic` ([modes](modes.md#modes)): supervised Claude Code workers start in auto mode, other agents' supervised workers in the mode Orca's agent permission setting gives, and every question to the owner waits for the owner; automatic workers start in `dontAsk` inside the sandbox once the checks of [Automatic start](modes.md#automatic-start) pass; a failed check runs the project supervised, except a failed `--check` read of an item, which blocks that item. The run argument `--mode supervised` lowers it; nothing raises it. An older plugin refuses the key, so a policy that sets it, or `sandbox`, names the first plugin version with them in `minPlugin` | `supervised` |
| `sandbox.allowedDomains` | the hosts an automatic worker's commands may reach, required when `mode` is `automatic`: what the project's own tools fetch, each a host name, or `*.` before a domain. A GitHub host runs the project supervised ([Automatic start](modes.md#automatic-start)): the coordinator pushes. `*.` on a shared-hosting suffix (`*.github.io`, `*.amazonaws.com`, `*.co.uk`) opens every tenant under it, and the reader resolves no name, so it does not see one that points at a local or metadata address | none |
| `review.depth`, `review.sensitiveDepth` | the review level of a routine and of a sensitive change (`low`, `medium`, `high`, `xhigh`) | both `high` |
| `riskyPaths` | paths whose change has high impact: the risk class is at least medium and the change sensitive ([Risk class](SKILL.md#risk-class)). An older plugin refuses the key, so a policy that sets it, or `merge.autoMergeMax`, names the first plugin version with them in `minPlugin` | none |
| `review.sensitivePaths` | paths that make a change sensitive, besides the built-in classes ([review-and-merge.md](review-and-merge.md#sensitive-or-routine)) | none |
| `models.worker` | model and effort of a worker session, printed as a table by depth (`quick`, `standard`, `deep`) and for `research` | quick `sonnet`, standard and deep `opus`, research `fable`, all `high` |
| `models.phases.<phase>` | model and effort of a worker's phase subagent (`plan`, `implement`, `test`, `review`, `research`), printed only for the phases the policy names; `inherit` is the worker's own model | the workflow skill's: plan, implement and review `opus`, test `sonnet`, research `fable`, each at `high` |
| `models.sensitive.<use>` | model and effort for a sensitive change: `plan` and `review`, the worker's Plan and Review phases; `independent`, the coordinator's reviewer; `security`, that reviewer for a change to authentication, permissions, secrets, input validation or firmware safety. Each field the policy leaves out keeps its default; `inherit` as in `models.phases`. An older plugin refuses the key, so a policy that sets it names the first plugin version with it in `minPlugin` | plan, review and independent `fable` at `high`, security `fable` at `xhigh`; an account without `fable` sets each `model` |
| `issues.labels` | labels an issue must carry besides `startLabel`; the issues live in the project's repository ([SKILL.md](SKILL.md#names)), so the reader drops an `issues.repository` with a warning | no further label |
| `minPlugin` | the oldest plugin version that may run this policy; on an older plugin the reader exits 1 | any |
